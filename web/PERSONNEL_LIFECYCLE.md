# 离职与岗位调整

人员与角色页面默认显示在职人员，可筛选已离职或全部。临时停用账号仍属在职，状态分开展示。

- “岗位调整”同时保存职位、组织、角色和直属上级。需要更高职级的上级和匹配的组织；若调整后不能继续管理现有下属，先调整其人员关系。保留原账号、密码和个人资料，员工重新登录获取更新后的权限。
- 有直属下属时优先使用“更换负责人”，选择接任人员与双方职位后，一次保存接任角色、原负责人普通员工角色及直属下属的新上级。部门内的团队和人员仍保持原组织结构，任务、日报、审批数据不变。原负责人之后可调岗或办理离职，不需要先取消负责人。
- “办理离职”填写实际离职日期并确认停用账号。即时生效，不支持未来预约。仍有在职直属下属时禁止办理；先通过岗位调整重新设置下属的直属上级。当前登录账号由其他管理员处理。
- 卡片会提前禁用不满足条件的“办理离职”。没有直属下属也不代表组织职责已解除；组织仍有人员/下级组织且没有其他负责人时，须先更换负责人。
- 离职人员保留历史资料和角色，禁止编辑、改岗位和重置密码，从上级候选中排除；可查看变动记录。无删除员工操作。
- “变动记录”仅展示人员职位、组织、角色、上下级、在职/账号状态及变更前后值、操作人和日期，不包含公司业务内容。

后端需部署 V6 和相应接口，见 `backend/PERSONNEL_LIFECYCLE.md`。本轮只本地验证，不部署云端；通用系统日志的 log/数据库选择仍待确认。
