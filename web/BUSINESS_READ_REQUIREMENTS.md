# Web 业务查看与标签规则（2026-10-16）

## 本次确认与范围

用户授权 Web 管理员查看工作日报、任务和统计，只读，不获得填写、审批、派发或验收入口。仍只修改 web/；遵照用户的目录限制，本次不写根目录 OpenSpec，也不修改后端。后续跨端变更应补正式 OpenSpec 并同步主需求文档。

- 新增工作日报、任务查询、工作统计导航，沿用现有身份和公司边界。
- 日期区间查询、人员/组织/关键词筛选、列表分页、全文详情，数据只来自真实接口。
- 查询使用现有 GET /work-logs?scope=managed、GET /tasks?scope=managed，获取全部游标页后筛选与统计；任务详情使用 GET /tasks/{id}。
- 展示范围是服务端实际授权返回的数据，不能宣称全公司；不切换业务身份、不给管理员附加创始人角色、不绕过权限。
- 统计来自完整查询结果：日报数、作者数、任务数、已批准任务的可见执行记录总数及完成数。完成以 executionStatus=COMPLETED 为准，不能用进度 100% 冒充完成。不使用 /statistics 冒充公司统计，该接口仅统计本人已批准执行记录。
- 权限拒绝、接口缺失、网络错误与“成功查询但无数据”分开显示；失败不显示零统计或演示数据。离开页面/注销丢弃未完成请求和业务快照。

## 甲方答复记录

- 标签：部门负责人及以上可修改；历史任务/日报使用修改后的名称颜色；不用的标签可停用且保留历史；同企业标签禁止重名。
- 本轮补充：能创建标签的角色应能删除，包含 Web 管理员。删除与历史关联保留仍需服务端采用一致策略；不能由 Web 静默删除历史关联，也不能把停用伪装成已删除。
- 公司重要事项：最多展示十条；超过后的选取/排序未确认，不把十条展示上限当作存储上限。
- 成员：直接生成账号和初始密码。首次强制改密、忘记密码流程未答复，本轮不擅自确定。

## 当前后端阻塞与交接

核查当前本地 dev 基线：

1. JournalService.list/detail、TaskService.query/detail 调用 Actor.business()；纯 ADMIN 角色被拒。需要管理员的企业内只读查询与详情授权，并保证返回已发布日报、限定企业、正确管理范围及可见执行人。客户端不自行提升权限。
2. 现有 managed 范围要求业务管理者；后端需明确是否扩展这些 GET 的 ADMIN 语义或提供独立管理 GET，再同步契约与 Web。当前 Web 按已有字段接入，403 明确提示服务未开放管理员查看。
3. TaskController 没有 DELETE /tags/{id}，也没有停用接口。TagService.patch 仅 ADMIN，create 不检查重名。当前不能实现真实删除/停用。Web 显示删除不可用，待确认正式路由、版本控制、关联保留语义后接入；不会发送猜测的写请求。
4. 管理员统计需覆盖同一授权范围与筛选条件；若新增服务端统计，必须说明统计对象、完成事实、时间字段与分页口径。
