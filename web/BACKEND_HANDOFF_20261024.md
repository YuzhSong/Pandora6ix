# 后端配合清单（2026-10-24）

## 1. 取消登录时填写公司标识

当前 `Contracts.Login` / `IdentityService.login` 按 `enterpriseDomain + loginName` 查询账号，账号只在公司内唯一。

- 若仅隐藏输入框：Web、Android 自动携带部署配置中的固定公司标识，现有接口可沿用；需要团队确认固定企业，不能任意猜测默认值。
- 若彻底取消接口字段：请后端明确单企业部署时由服务端配置可信企业，或多企业时提供不歧义的账号识别规则。重名账号必须明确拒绝，不能选择第一条匹配，继续保持企业隔离。
- 确定请求、错误码及兼容期后，Web 和 Android 分别修改界面和请求；Android 界面不会随服务端修改自动消失。
- 验收：两端仅输入账号和密码可以登录；重名、停用、已离职、错误密码和企业隔离均符合既有规则。

## 2. 日志返回真实版本号

已核对 `OperationLogService.snapshot`：当前固定返回 `version: 0`，并非人员记录的真实版本。

- 写日志时保存当次修改前后真实版本；如不支持版本则返回明确的可选版本/能力信息，不用 0 充当缺省值。
- 已存在的历史日志没有真实版本时，不应通过记录排序编造编号。
- 验收：连续修改同一对象得到可核对的前后版本，创建、离职、更换负责人等场景明确一致。

## 3. 提供真实历史版本列表

当前 `OperationLogService.detail` 的 `versions` 仅包含当前日志本身且版本固定为 0，没有查询同一操作对象的历史。

- 按企业、对象类型、对象 ID 查询真实已成功提交的历史记录，稳定排序。
- 返回可读取的历史 logId、真实可用版本、操作人、动作和时间，禁止跨企业查询。
- 失败操作不得当成已提交版本。
- 验收：修改同一对象两次后，可在列表中打开先前快照；无历史时返回空列表。

## 4. 建议补全日志的历史可读信息

当前 snapshot 把字段 key 同时用作 label，并将组织、上级以内部 ID 展示。

- Web 已完成中文字段和状态映射，并按当前目录解析组织、人员名称。
- 若甲方需要准确查看“操作当时”的组织、人员名称，后端应在日志中记录当时的名称快照，而非以后查询时按新名称覆盖。
- 保持标识与历史名称分离，并继续排除密码、令牌、证件号等敏感内容。
- 日志详情已有 requestId 字段，请确认实际异常请求也能提供可关联服务端日志的有效值。
