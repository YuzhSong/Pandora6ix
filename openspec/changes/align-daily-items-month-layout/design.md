## Context

DailyItemsPanel 的周行高为 40dp，仅显示日期和打点。公司 MonthScrollRow 使用 30dp 日期行、三道 18dp 事项条（道间距 3dp）和 16dp 溢出行。每日事项是单日数据，无需跨日分道。

## Goals / Non-Goals

**Goals:** 日期下直接预览事项，固定周行高度，溢出数量正对日期列，修改清单后立即刷新。

**Non-Goals:** 不修改本地数据结构、公司任务排序和审批，不增加事项业务功能。

## Decisions

- 在 PandoraCalendarDimens 中共享月视图容量、日期行高、道间距和溢出行尺寸，让两处使用同一尺寸来源。保留公司月视图已有显示行为。
- 每个日期列独立显示当天前三条事项，保持原清单顺序；单日事项无需转换成公司 TaskItem，避免引入任务优先级和审批语义。
- 每列完整保留三道空间，第四行显示灰色 `+N`；事项条填满本日期列可用宽度，单行省略，已完成事项为弱色加删除线。
- 日期列整体可点击，打开已有单日弹窗；溢出行提供明确的无障碍点击标签。
- 保留现有月份滚动及圆形选中日，去掉圆点预览。选择以最小布局改动满足要求，不重构公司月历滚动模型。

## Risks / Trade-offs

- [固定行高增加月份高度] → 沿用现有纵向月份滚动，确保每周固定高度，不挤压事项。
- [窄屏长标题难以读全] → 单行省略，点击任意事项打开完整清单。
- [旧未归档需求仍描述打点] → 本变更明确覆盖 android-home-redesign 的预览限制；其余交互保持原定义，归档时需按变更顺序处理。
