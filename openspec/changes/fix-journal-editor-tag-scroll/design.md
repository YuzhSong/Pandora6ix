## Context

日志弹层用固定高度 Card 包含日期和标签，仅工作输入区有 weight(1f) 和 verticalScroll。标签换行增多后，非加权内容耗尽可用高度，滚动输入区降为零。

## Goals / Non-Goals

Goals: 全选标签后仍能滚动到全部工作条目并填写；键盘弹出后保留可用编辑区和底部发布操作。
Non-Goals: 修改标签数量限制、日志提交规则和接口。

## Decisions

- 标题与说明在顶部，取消/发布在底部；两者之间使用一个 weight(1f).verticalScroll 的表单容器，包含日期、标签和工作条目。
- 工作条目内部移除 weight 与纵向滚动，避免同方向嵌套滚动及无界高度测量。
- 沿用 imePadding，但移除键盘显示时隐藏日期和标签的分支；字段结构保持稳定，输入后可手动滚回标签区域。打开标签选择器前清除正文焦点，避免键盘高度变化触发正文光标定位。
- 六行限制未解决设备上的遮挡问题，改用 BasicTextField + 原 OutlinedTextField 装饰，保留 TextFieldValue 的光标、选区与输入法组合状态，通过 onTextLayout 获取实际光标矩形。
- 工作输入框最少两行，随正文自然增高，不另设内部纵向滚动。BringIntoViewRequester 附着于装饰内的文字容器，使光标矩形坐标直接对应请求区域；在内容、选区、焦点及键盘高度变化后等待布局帧，主动要求外层表单滚动到光标行并留出边距。
- 只对获得焦点的输入框请求滚动；手动滑动不触发请求，移动光标到中间编辑时跟随实际位置，不强制滚到文末。
- 日志标签选择器为已选的非主标签提供“设为主”，将该标签移到 tags 首位且保留其他标签次序，复用现有提交链路从首位生成 primaryTagId；操作区和勾选位固定占位，取消整行黄色高亮。

## Risks / Trade-offs

- 键盘展开导致表单高度变化 → 使用统一滚动视口和 Compose 输入框的焦点滚动能力；需设备验证小屏、多标签、多条目。
