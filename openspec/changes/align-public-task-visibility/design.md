## Context

截至 PR #56，任务汇总采用独立的横屏工具栏。PR #57 定义全公司任务的列表可见范围、任务详情内容及 Android 通知行为，这些改动以其最新提交为准。 [PR #57](https://github.com/YuzhSong/Pandora6ix/pull/57)

## Goals / Non-Goals

- 同企业用户通过任务列表和日历发现已生效的全公司任务。读取范围和写入授权各自由服务端判定。
- 用现有的执行关系、任务审计及通知记录呈现状态。日志留言删除入口的变更限于 Android 界面。

## Decisions

- 列表和日历复用 `TaskService` 的 `mine` 查询。查询包含当前用户的已审批执行任务以及企业内已审批的全公司任务，避免两个入口产生不同口径。任务详情保留任务级读取校验，透出完整的当前执行关系，每条关系的可用操作仍单独计算。
- 详情的 `editedAt` 取该任务最近的 `TASK` 更新审计。生效的内容编辑集中在 `applyContent` 记录审计，复用现有数据。
- 查看任务和审批详情时，Android 按 `taskId` 或 `reviewId` 匹配通知并提交已读。审批结果先读取授权详情，读取失败时打开关联任务。独立的待审批和待验收计数用于审批角标。
- 保留 PR #56 的横屏布局，将 PR #57 对刷新按钮的移除应用到提取后的工具栏和对应布局测试。同步修正横屏规格中对该按钮的描述。

## Risks / Trade-offs

- 同一个任务有多个执行人时，集成测试按 `recipientUserId` 选中当前用户的执行关系，使权限断言始终针对同一个业务对象。
- 全公司任务包含执行记录和验收申请历史，查询以企业和任务读取权限为边界。写操作继续检查角色、执行关系和版本。

## Migration Plan

先发布后端，再构建和分发 Android。`editedAt` 是可选响应字段，发布使用现有数据表和迁移记录。
