# Design

## Context
See proposal.md. 上级与组织独立；岗位请求复用会写审计的 patchUser；旧记录可能没有名称快照。

## Goals / Non-Goals
使组织调整明确可见、历史可读、审计不重复。不改历史事实、不改数据库。

## Decisions
普通员工默认勾选随上级转组，手动选组织取消联动。管理岗位仍需显式选择角色匹配组织。候选复用组织路径标签。历史完整展示岗位上下文，旧 ID 用明确的当前参考名称或原始标识，绝不回填数据库。内部 patchUserForLifecycle 复用校验但不写通用日志，入口事务仍负责唯一生命周期日志。

## Risks / Trade-offs
旧快照无法恢复当时名称 → 明确标记参考信息。后端审计改动 → 集成测试检查单一操作及真实版本。

## Follow-up correction
所有人员入口复用普通员工上级组织推导。选择上级触发可见组织更新，避免旧的关闭联动状态使转组失效；后续手动选择仍允许独立归属。批量未填组织按上级推导。岗位提交校验返回的组织、上级、角色及版本。云端后端尚未发布本地审计去重，明确区分部署状态。密码先核实随机初始密码与 bcrypt 哈希的区别，不修改认证存储。

## 2026-10-31 表单精简与自动账号
新增单人草稿初始化时生成 emp_ 前缀随机账号，检查现有账号大小写无关冲突并追加序号。账号随草稿保持稳定，新建只读、编辑仍保留原行为。移除新增的说明段落与已变更后缀，保留真实历史引用来源标识以免把当前名称当成历史事实。

## 手机端交付
新初始密码采用12位小写字母与数字，保持crypto随机数拒绝采样并避开易混淆字符。交付文本和Excel增加企业域/登录名，界面只加必要字段不加说明段落。密码原值复制，已有密码只允许经正常重置修改。本地Android仍采用enterpriseDomain/loginName/password三字段登录，未验证用户安装APK版本。

## 姓名拼音账号与数字密码
新增人员输入姓名时生成无声调小写全拼账号，已有账号冲突追加数字序号；已有人员不改账号。批量新增未填账号时按姓名补全，保留显式账号。采用拼音库处理中文，密码保持12位密码学随机数字，原样交付。

## Excel 开发服务依赖缓存
ExcelJS 按需加载在本地服务返回504 Outdated Optimize Dep。显式纳入Vite预构建，重启服务强制重建依赖缓存；保留生产导出逻辑。
