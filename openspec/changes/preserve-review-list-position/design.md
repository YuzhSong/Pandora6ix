## Context

ReviewScreen 在详情分支提前 return，LazyColumn 默认内部状态随列表销毁。返回和 30 秒刷新都调用非追加加载，将已加载列表缩成第一页。

“我的”页面在打开审批中心、设置和标签管理时退出组合，内部 rememberScrollState 同样会销毁。

## Goals / Non-Goals

Goals: 同一审批队列内详情往返保持首个可见条目和像素偏移，保留已加载分页，继续响应已读和审批结果更新。
从“我的”进入子页面再返回时保留原滚动偏移。
Non-Goals: 跨退出审批中心、进程重启恢复列表数据，或新增后台接口。

## Decisions

- 在详情分支之前创建 LazyListState，通过 LazyColumn 的 state 参数传入。切换队列时重置该队列会话的列表与分页状态。
- 在 PandoraApp 页面分支之外按 currentUser.id 创建并保存“我的”ScrollState，显式传给 ProfileScreen；退出登录或切换账号时重置，不使用页面内部新建状态。
- 记录成功加载的页数。非追加刷新从第一页开始沿最新游标拉取同样页数，全部成功后一次替换，保留稳定 review.id key 与滚动状态；返回、审批成功与定时刷新共用此逻辑。
- 服务端已无后续页时提前结束并更新页数；分页失败保留现有列表、游标、页数，可重试，避免半成品数据缩短列表。
- 保留现有请求代次和 scope 校验，避免旧队列结果覆盖当前队列。刷新期间禁用加载更多，避免重复追加。

## Risks / Trade-offs

- 深层分页刷新请求数增加 → 只刷新实际已加载页，不扫描全部历史。
- 审批后记录可能离开待审队列 → 使用稳定条目 key，保留邻近浏览位置；列表缩短时由 LazyListState 约束到合法位置。
- 模拟器 UI 验证依赖设备 → 明确记录未执行的人工验证，不将单元测试视为 UI 验证。
