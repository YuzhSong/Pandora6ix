## Context

- 公司页面即 `CalendarScreen`（底部导航“公司”），顶部有“我的任务 / 我管理的 / 我创建的”范围芯片，`MainActivity` 持有 `taskScope` 并以它请求日历接口。
- 任务汇总为 `ui/summary/TaskSummaryFlow.kt`：总览三面板（任务预览、直属下属、最近日志）+ 组织架构、成员详情、全部任务、全部日志四个二级页。分页由 `SummaryPager` 负责。
- 任务列表接口（`full=false`）不返回进度记录；执行关系 `authorizedAssignments` 带 `progressPercent` 与 `recipientName`。
- `GET /work-logs` 已支持 `date`、`from`、`to` 与 `scope=managed`；日志接口没有按作者过滤的参数。

## Goals / Non-Goals

**Goals：** 甲方要求的表格式任务汇总，在竖屏手机上可用、横屏一屏看全；公司页只显示自己的任务；通讯录承接下属内容并支持日志按日期筛选。

**Non-Goals：** 不做表格内编辑、列排序/自定义列；不新增权限规则；不改日历视图本身。

## Decisions

### 1. 表格：冻结首列 + 同步横向滚动（而非卡片或缩小字号）
甲方明确要表格，因此保留表格的行列结构，用电子表格 App 在手机上的常见做法解决宽度问题：
- **首列“任务名称”固定在左侧**（约 136dp，最多两行），左右滑动时始终知道当前行是哪个任务；
- 其余五列放进同一个 `ScrollState` 驱动的横向滚动区，表头和每一行共享该状态，任意一行滑动整表同步；
- **表头固定**在面板顶部，纵向用 `LazyColumn` 分页加载；
- 列宽：截止日期 92、紧急程度 72、完成情况 84、进度备注 200、负责人 120（dp），竖屏 360dp 宽度下首屏可见任务名称 + 截止日期 + 紧急程度 + 完成情况，右侧露出半列提示可以滑动；
- 右上角“横屏查看”把 Activity 切到横屏（离开汇总或再次点按恢复竖屏），横屏宽度可以一屏显示全部列。`MainActivity` 声明处理 `orientation|screenSize|screenLayout|smallestScreenSize`，旋转时不重建 Activity，登录态和页面状态不丢失；
- 按主标签分组：组标题行横跨整行、浅色底（对应参考表格中的“自营产品”等分组行），没有主标签的任务归入“未分组”放在最后；组内保持服务端返回顺序。
- 备选：缩小字号把六列塞进一屏——可读性和触控区不达标，放弃；仅提供横屏——竖屏也需要能用，放弃。

### 2. 表格单元格内容
| 列 | 内容 |
|---|---|
| 任务名称 | 标题，未通过审批的任务在名称下显示审批状态小字 |
| 截止日期 | `endDate`（带时间的任务显示 `MM-dd HH:mm`，全天任务显示 `yyyy/MM/dd`） |
| 紧急程度 | 现有优先级标签与色调芯片（`priorityLabel` / `priorityTone`） |
| 完成情况 | 现有完成状态标签与色调芯片（未开始 / 进行中 / 待验收 / 已完成…） |
| 进度备注 | 后端 `latestProgressNote`；无备注时显示可见执行关系的平均进度“进度 x%”，0% 显示“—” |
| 负责人 | 执行人姓名（`executorName`），多人用“、”连接，最多两行 |

### 3. 后端 `latestProgressNote`
在任务视图（列表与详情共用）中，对当前用户可见的执行关系（`authorizedAssignments`）查询最近一条 `note` 非空的进度记录：`ORDER BY recorded_at DESC, id DESC`，取第一条。可见范围与详情中的 `progressRecords` 完全一致，不扩大授权。每页最多 100 个任务，每个任务一条索引查询（`task_progress_record` 已有 assignment 索引），可接受。

### 4. 公司页面只看自己的任务
删除范围芯片与 `managed` 403 回退逻辑，`MainActivity` 以常量 `scope=mine` 请求日历。下属任务仍可在任务汇总“下属任务”标签中查看。

### 5. 通讯录
新增 `ContactsFlow`（与 `TaskSummaryFlow` 同包，复用面板、分页与行组件）：
- 根页：直属下属完整列表（头像、姓名、职位，点击进成员详情）、“组织架构”入口、“下属日志”入口；
- 成员详情：沿用原成员页（个人信息与电话、负责的任务、最近日志），“查看全部”进入该成员的日志列表；
- 日志列表：顶部日期筛选芯片（全部 / 今天 / 近 7 天 / 本月 / 指定日期），指定日期使用已有 `DateWheelDialog`；筛选变化时以新的 `from/to` 重新建立分页器，按成员过滤仍在客户端进行，已加载范围为空且还有下一页时提示继续加载（与现有规则一致）。
- 无管理能力的账号打开通讯录时显示“当前账号没有下属查看权限”，不发起候选人请求。

## Risks / Trade-offs

- [竖屏仍需横向滑动] → 冻结首列 + 露出半列 + 横屏按钮；这是甲方接受的方式。
- [横屏切换影响其他页面] → 仅汇总页可切换；离开汇总时恢复竖屏（`DisposableEffect`）。
- [列表接口多一次查询] → 单条索引查询，分页上限 100。

## Migration Plan

客户端与后端同时发布；`latestProgressNote` 为新增可空字段，旧客户端忽略。回滚即恢复原汇总页与范围芯片。
