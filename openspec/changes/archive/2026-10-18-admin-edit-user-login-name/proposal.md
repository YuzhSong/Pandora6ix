## Why

管理员希望把模拟员工的登录名改为姓名拼音，但当前后端人员修改契约没有 loginName，Web 也禁用了该字段并拒绝提交修改。需要支持管理员维护现有账号的登录名，保留同一员工的身份和业务记录。

## What Changes

- 为现有 `PATCH /api/v1/admin/users/{id}` 增加可选 `loginName`，省略或 null 时保留原值。
- 仅本公司 ADMIN 可修改；登录名非空白、不含首尾空白且最长 128 字符，同公司内唯一，遵循既有精确匹配/大小写语义。
- 保留 expectedVersion 并发控制，重名或无权限时整笔拒绝；更新同一用户，不重建账号，不修改密码、角色、组织、人员资料或业务关联。
- 新登录名配合原密码可登录，旧登录名不再登录；已有基于用户 ID 的会话保持有效，停用仍按现有规则撤销会话。
- 按用户确认一并接通 Web 登录名编辑、请求和重名提示，验证服务端返回的新登录名，防止旧后端忽略字段却显示保存成功。
- 编辑历史资料为空的账号时，登录名修改不强制补全尚未修改的性别/身份证/电话；创建新员工和实际修改资料仍沿用必填校验。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `backend-identity-directory`: 增加管理员修改本公司现有账号登录名的要求。
- `organization-directory`: 在人员编辑中支持登录名变更并确认实际保存结果。

## Impact

在已同步最新 dev 的 backend-syz 上修改人员更新 DTO、服务、接口文档与后端集成测试，以及 Web 人员编辑和 HTTP 仓库的最小配套改动与测试；不新增接口、数据表、依赖或生产数据脚本。提交 PR 到 dev，暂不合并或部署，不自动批量改动真实/模拟员工账号。
