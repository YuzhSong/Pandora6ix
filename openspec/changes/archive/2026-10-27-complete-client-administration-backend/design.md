## Context

用户授权合并 #12/#13 到 dev，并同步 backend-syz 实施后端配合事项。已合并 dev a493dfe。沿用 Java 21/Spring/JDBC/H2、现有管理员接口和企业锁；不引入服务或账号。系统操作日志方案尚未确认。

## Goals / Non-Goals

Goals: 真实保存组织转换与人员资料；约束同公司管理员权限；提供稳定部门分组信息；验证迁移、版本、并发与跨企业边界。

Non-Goals: 审计事件存储/查询、头像上传、员工注册、首次改密策略、数据库产品替换及未确认的业务流程。

## Decisions

1. 组织变更复用 enterprise 行锁，与人员编辑共用串行边界，确保负责人角色检查不会与改角色并发穿透。保持 ID，拒绝带子组织或不匹配负责人类型转换；部门直属公司，团队直属部门。不自动搬迁成员或授予管理角色。
2. V3 只新增可空 VARCHAR gender/id_number/phone_number，保留历史记录。创建通过 Jakarta 校验与电话数字数量校验；gender 使用 Web 提议的 MALE/FEMALE，身份证仅做已确认基本格式。PATCH null/省略均保留旧值，不提供隐式清空语义。复用现有事务原子创建账号和角色。
3. 通用 BusinessDb.view 排除三字段；DirectoryService 的受权 user 投影显式补回。避免 SELECT * 在 /me 或下属响应意外扩散身份证。OpenAPI 分开 User（管理员）和 Profile（本人）。不把输入值打印进验证证据。
4. 初始化只允许部署 bootstrap secret，不能用公司 ADMIN 跨企业开通；不强制数据库只保留一家公司以免破坏隔离回归与部署复用。纯 ADMIN 的标签读写收敛，业务创始人/部门负责人可维护标签，现有公司事项管理保留。
5. 候选 SQL 保留组织信息，并 LEFT JOIN 当前部门或团队的父部门，显式返回 departmentId/departmentName；客户端按稳定 ID 分组并遍历 nextCursor。没有部门的公司级成员独立分组，不泄露其他组织或个人字段。

6. 用户在本轮明确覆盖 PR #13 的滚动 24 小时策略：工作日期为企业 today 才允许作者 PATCH/DELETE。today-1/today-2 仅允许首次 POST，提交后只读；新建拒绝其他日期，历史读取和十日个人重要事项候选保持原边界。响应携带 businessToday 与 allowedActions，Android 用企业时区日期选项和服务端动作限制编辑；跨日命令由服务端重新判断。

## Risks / Trade-offs

- 新建人员三项必填是契约收紧；同步 smoke 和 Web 联调脚本，历史 null 可继续编辑。身份证字段格式与 Web 一致，不能将基本格式视为实名核验。
- 旧客户端省略资料仍能 PATCH，但不能清空已存资料；明确文档约定。
- bootstrap 接口本地回归可用，云端原配置已关闭，发布后确认管理员绕过也不可用。
- 操作日志仍未实施，不能声称本轮已有全面审计；甲方确认后单独建变更。
