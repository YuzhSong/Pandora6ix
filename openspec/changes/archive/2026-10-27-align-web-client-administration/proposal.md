# Proposal

## Why

甲方只需要本公司的管理端，管理员负责组织、人员、权限与系统操作追溯，不参与员工任务、日报和标签业务。现有公司开通入口、业务导航及不完整人员资料不符合本次确认的范围。

## What Changes

- 删除 Web 公司开通入口及标签管理页面，移除管理员日报、任务和统计入口。
- 开放部门/团队类型编辑，校验子组织、负责人角色和上下级关系；后端拒绝时保留草稿。
- 人员创建与账号创建使用同一请求；加入性别、身份证号、电话必填项，员工没有自助注册入口。
- 增加系统日志待接入页与需求清单，覆盖任务/日报增删改等操作；文件 log 或数据库由甲方确认后实现。
- 本次仅改 Web。新增人员资料接口尚未就绪时拒绝不完整创建，不声称字段已保存；记录后端配合契约。
- 人员按组织分组时以部门、团队两层独立展开，部门直属人员与团队成员分开展示，保留筛选与角色分组。
- 默认展开公司和部门、收起团队；组织选项增加可见层级符号。
- 管理员头像可更换，当前无后端头像接口，存储范围依用户确认；公司事项支持拖动及按钮排序，按完整列表从 1 编号并通过既有 PATCH 接口保存。

## Capabilities

### New Capabilities

- `system-operation-audit`: 系统操作日志范围及存储决策未定时的明确待接入状态。

### Modified Capabilities

- `web-admin-shell`: 单公司管理入口、去除业务页面和标签加载。
- `organization-directory`: 人员资料与账号同步创建、组织类型编辑和兼容旧接口的失败保护。
- `web-account-preferences`: 管理员头像修改及实际存储范围提示。
- `company-important-maintenance`: 事项卡片拖动排序、顺序保存及部分失败反馈。

## Impact

仅修改 web/ 和本变更的 OpenSpec 文档，不修改 backend/、android/，不自动合并或部署。后端需配合组织类型校验、新人员字段的持久化及返回；审计接口待存储方案确认。
