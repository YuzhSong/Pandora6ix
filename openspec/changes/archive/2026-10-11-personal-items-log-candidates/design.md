# 设计说明

## 数据流

- `logs`（已发布日报的 `SnapshotStateList`）已在 `PandoraApp` 提升，随 `HomeScreen` 传入 `PersonalImportantEditor`，因此日志页新发布的条目无需额外通信即可进入候选池。
- 候选在编辑器内按需派生（非 remember 缓存）：`logs.filter { 本人 && 日期 ∈ [今天-9, 今天] }.sortedByDescending { 日期 }.filter { 内容 ∉ 正式事项 }`，读快照列表即建立订阅，正式事项增删或日志发布都会触发重算。
- 候选按「日报内容文本」与正式事项匹配：垃圾桶移除正式事项后，原日报条目自然回到候选区；被编辑过文字的正式事项移回时以原日报条目重新出现（编辑版随之丢弃），符合「候选=日报原文」的语义。

## 交互

- 正式区保持既有样式（序号圆 + 文字 + 垃圾桶、长按拖动排序、点文字编辑），仅垃圾桶语义从「删除」改为「移回候选」，弹窗标题 / 正文 / 按钮文案同步调整。
- 分割线复用 `DashedDivider`，与全站虚线分隔风格一致。
- 候选行：`Checkbox`（WarmOrange 配色）+ 条目文字（最多两行省略）+ 右侧日期小字（M月d日）。打钩即 `items.add(content)`；`enabled = items.size < 10` 实现上限，满时追加提示行。
- 顶部按钮「完成」→「保存」；由于编辑器直接操作共享的 `personalItems` 快照列表，保存关闭后导图面板即为最新内容。

## 取舍

- 移除「添加新事项」自由输入：正式事项来源统一收敛为日报候选，避免出现无法回到候选池的「孤儿」手动条目。
- 演示数据 `MockData.logs` 日期改为 `shifted(...)` 跟随真实今天平移（与任务同策略），否则「最近十个自然日」窗口内永远没有已发布日报，候选恒为空、特性不可演示。
