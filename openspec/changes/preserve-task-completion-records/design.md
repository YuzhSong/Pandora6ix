## Context

日历和任务详情在同一 calRetry 触发后分别请求简略列表和完整详情，共用 taskDtoById，最后返回的列表可能覆盖详情。个人完成旧接口不携带阶段文字；重复任务现有 scoped-status 接受 note，但个人完成分支未保存 note。

## Goals / Non-Goals

**Goals:** 完成后保留已保存记录，输入的完成说明原子进入执行历史；失败保留草稿。

**Non-Goals:** 改变审批/验收、批量范围、授权或新增 API/表。

## Decisions

- 主入口复用 SummaryTaskDetail 的独立详情状态，日历列表刷新不参与详情数据写入；不采用列表/详情混合缓存合并以免保留过期字段。
- 普通任务复用 scoped-status 的 SINGLE 范围，携带现有任务及执行关系版本和 note，避免先保存文字再完成产生两次非原子写入。
- setWorkStatus 完成分支在原事务内追加非空文字记录，个人与派发一致；派发仍保存验收说明，历史原有条目不改不删。旧 complete API 保持兼容。
- 请求失败不清空输入；成功后刷新完整详情，幂等键维持现有语义。

## Risks / Trade-offs

- 新客户端完成文字需要后端修复部署 → 联调使用同批次版本验证；无数据库迁移。
- 并发更新或重复请求 → 现有版本与幂等检查保障拒绝或重放，不重复追加历史。
