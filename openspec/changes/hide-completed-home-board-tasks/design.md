## Context

首页以 `GET /tasks?scope=mine` 分页读取任务。一个任务可能有多个可见执行关系，完成判定必须使用当前用户的 `executionStatus`，不能使用其他人的完成状态或进度百分比。

## Goals / Non-Goals

**Goals:** 首页紧凑列表、展开列表、计数和详情跳转使用同一过滤结果；分页中全为已完成的页不能遮挡后续未完成任务。

**Non-Goals:** 不修改其他列表、任务生命周期、验收规则或服务端 API。

## Decisions

- 传入当前用户 ID，以其执行关系的 `executionStatus == COMPLETED` 为排除依据；待验收、ACTIVE 和缺少本人执行关系的数据保持原显示策略。不能以 `workStatus` 或 100% 进度判定完成，因为仍可能需要验收。
- 抽出首页专用分页函数，复用现有 tasks 查询与游标，过滤后无可见条目且存在下一页时继续读取，直到读到可见任务或末页。首次加载和加载更多共同使用该函数。
- 过滤后的任务直接存入原 taskPager，确保标题、计数和点击 ID 对齐。
- 用单元测试覆盖多人状态、待验收、连续空页、结束游标和失败重试起点；不引入后端筛选参数。

## Risks / Trade-offs

- 连续已完成页较多导致请求增加 → 串行读取至首个可见页，保留加载态，不提前显示空态。
- 中间页请求失败 → 不修改 UI 已提交的游标及列表，允许从原游标重试。
