## Context

`DailyItemsPanel` 目前按日期分组，在单日弹窗内录入内容。`DailyItemsStore` 按账号保存本地 JSON，记录包含 ID、日期、内容和完成状态。`initialJournalEntries` 按记录日期预填全新的日志草稿。

## Goals / Non-Goals

- **Goals** 让用户从首页直接创建定时或全天待办，在月历上查看跨度并按日拖动改期，也能打开详情编辑原记录。
- **Non-Goals** 任务派发、审批、统计、提醒和账号间同步不在本次范围内。

## Decisions

- 保留现有日期字段作为开始日期，新增可缺省的结束日期和起止分钟。旧数据缺少结束日期时以原日期作为结束，两端均缺少分钟时表示全天。读取兼容旧 JSON，无需启动时重写。为日志保留按事项开始日期预填的行为，跨日事项只在其开始日参与预填。
- 新增、详情与编辑均按事项 ID 操作。复用任务表单的日期、时间选择控件和时间区间校验，使用独立的待办表单，避免任务派发、截止时间与提前量等业务规则影响本机待办。新建默认以面板选中日期为起点，两端均可调整。
- 全天采用含首尾日期的范围，单日全天占满一天。定时采用本地日期和墙上时钟分钟的半开区间。覆盖日期、日清单和月历布局共享同一套范围计算，恰在次日 00:00 结束的事项只占前一天。
- 抽取或复用公司月视图按周裁剪、分道、计算每列溢出的逻辑，为待办提供稳定的排序和 ID。跨周或跨月段的绘制引用同一记录，沿用首页紧凑行高、已完成弱色和删除线。日期和溢出入口打开日清单，点击事项条或清单正文打开详情。
- 全天事项以原开始日到落点的日数为偏移，定时事项以按住的日期列到落点的日数为偏移。两端日期一起平移，保留起止分钟、全天状态、完成状态与内容。拖回按住的日期列或偏移为零时无需保存。拖动中高亮有效目标，边缘滚动时以当前可见网格做命中检测。松手落在有效日期才保存一次。编辑和拖动都由同一按 ID 更新的入口保存，由首页和日清单从更新后的记录重算显示。

## Risks / Trade-offs

- 跨日条在后续日期也可抓取。拖动定时事项时用手指命中的日期列计算偏移，使落点对应原先抓取的日期。
- 手势取消、拖出面板、命中月历空白或平移后超出可选日期范围时清除预览并保留原记录。普通轻点、月历滚动、完成和删除各自保留原有操作入口。
- 只在绘制的周或月范围内裁剪和分道，避免长跨度待办在连续月份列表中提前展开为逐日记录。
