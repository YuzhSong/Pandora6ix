# Proposal

## Why

创始人是企业最高业务负责人，没有直属业务上级可执行审批。当前创建任务仍强制写入上级审批，导致创始人无法正常提交任务。

## What Changes

- 创始人创建的个人或派发任务直接进入已批准、可执行状态。
- 非创始人继续要求有效的直属上级审批，保持现有拒绝规则。
- 增加创始人直通审批的集成测试，并保留任务与执行记录的一致性。

## Capabilities

### New Capabilities

### Modified Capabilities
- `backend-task-workflow`: 创始人创建任务时免除直属上级审批并直接激活任务。

## Impact

影响后端任务创建服务、任务审批状态/分配状态和集成测试；不新增数据库表或外部依赖。部署后既有任务不变，仅影响新创建任务。
