# Design

## Context

任务创建目前统一要求创建者存在有效直属上级，并写入待审批记录。`FOUNDER` 的业务等级为最高级，组织模型允许其没有直属上级。

## Goals / Non-Goals

**Goals:**

- 仅对包含 `FOUNDER` 业务角色的创建者跳过审批。
- 新任务直接标记为批准并激活全部任务分配，返回结果与普通批准任务一致。
- 保持非创始人的审批、权限和版本校验不变。

**Non-Goals:**

- 不改变已有任务、审批决定接口或普通用户审批流程。
- 不把 `ADMIN` 角色单独视为免审批角色。

## Decisions

在任务创建事务内按服务端业务角色分支：创始人不创建待审批记录，而是创建已批准任务并将分配状态设为 `ACTIVE`；其他角色沿用现有直属上级快照流程。选择服务端角色判断而不是前端绕过，确保 API 与所有客户端一致。

## Risks / Trade-offs

[错误授予免审批] → 仅检查 `FOUNDER` 业务角色，不以 `ADMIN` 或客户端字段为依据，并增加回归测试。

[任务创建与激活不一致] → 在同一事务内写入任务状态和分配状态，失败时整体回滚。
