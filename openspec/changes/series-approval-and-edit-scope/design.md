## Context

当前每次创建独立审批且详情缺少完整编辑入口，状态仍走单次完成接口。

## Goals / Non-Goals

目标：一次创建审批、本次/未来范围保存、简洁界面。非目标：更改派发任务的验收权限或跨组操作。

## Decisions

首次任务承载组创建审批，审批时锁定全组并验证所有成员上下文，整组原子生效或拒绝。V13 occurrence_date 保存不可变发生日期；范围以所选发生日期而非编辑后的日期判断。新增 scoped-edit/scoped-status 命令携带所有目标版本，任一过期或权限失败整组回滚；元数据、执行人不可通过详情编辑改派。重复详情已批准后直接编辑，普通任务仍沿用审批规则。状态沿用本人权限及派发验收流程；已完成个人任务可恢复未完成。未来详情日期按选中任务的位移应用，各次日期间隔保留。创建审批前重复任务不可编辑，避免快照失效。客户端从服务端读取范围版本快照，保存后询问范围；取消不写入。

清理表单的规则说明、标签说明和审批脚注；保留控件标签、必要的规则值/日期/次数与错误，不以灰色小字解释交互。

## Risks / Trade-offs

批量操作冲突 → 显式版本映射与统一锁顺序，失败无部分修改。非今日任务 → 按钮显示实际日期。本次迭代更改整组详情后，重复规则标签保留为创建来源，实际时间以单次任务为准。

## Migration Plan

V13 回填已有重复任务 occurrence_date。旧组若保留多条审批，首次整组决定时同步其未决创建审批结果；新组只创建一条。
