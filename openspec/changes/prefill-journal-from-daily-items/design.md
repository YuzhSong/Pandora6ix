## Context

LogsScreen 使用普通多行文本正文、已有条目和本地 JournalDraftDto。每日事项由当前账号 DailyItemsStore 保存 ISO 日期和完成状态。正文初始化有打开编辑器、切换日志日期两个入口。

## Goals / Non-Goals

**Goals:** 新建日志以当天 todo 作为可编辑的 Markdown 默认文本；保留删除、自由追加、草稿恢复及已有日志补充。

**Non-Goals:** 不自动判断实际工作完成、不修改 todo、不渲染新的富文本编辑器、不增加发布接口。

## Decisions

- 将共享的当前账号 DailyItemsStore 传给 LogsScreen，在初始化新日志时读取最新数据，按日志 dateKey 精确匹配，不依赖设备今天或 done 字段。
- 使用一条普通日志正文，格式为 `- 事项一\n- 事项二\n\n`。不增加复选框状态，列表末尾保留空行，加载正文时光标定位末尾，允许直接写其他日志；多行事项的续行缩进两格以保留同一 Markdown 列表项。正常输入时仍保留用户自己的光标位置及输入法状态。
- 用纯函数实现初始化优先级：日期草稿（包括用户清空的空内容）优先于已有日志，最后才是 todo 模板。只在进入日期时初始化，不随输入或重组重复注入。相比持续同步 todo，这能避免覆盖用户删除和追加内容。
- 同次编辑缓存各日期的正文和标签，切换前保存，返回时恢复；发布成功或明确放弃后清空会话缓存及内存草稿引用，防止旧模板重现。沿用现有磁盘单份草稿，仅当前日期落盘，不扩大持久化模型。

## Risks / Trade-offs

- [已完成 todo 可能不是实际完成工作] → 全部带入供用户自由删除，符合用户要求。
- [切换日期导致已删除模板重新生成] → 以是否存在草稿而非正文是否为空判定恢复。
- [重启仅能恢复当前编辑日期] → 保持现有单份磁盘草稿行为；本次新增的日期切换缓存只在编辑会话内生效。
