## Context

PandoraApp 的启动 runCatching 将网络、解析与取消异常都转换为 currentUser=null，然后显示登录表单。实机存在会话且显示登录页，没有捕获到崩溃；旧安装包叠加了热更新覆盖层。现有失效回调从 IO 线程 post 到主线程，执行时没有重查是否已有新登录。

## Goals / Non-Goals

**Goals:** 未知网络状态不等于未登录；明确重试；取消与旧响应不得发布状态；完整包实机复测。

**Non-Goals:** 不改服务器认证策略、不保存密码、不清除应用数据，不将尚未复现的闪动归因于确定的 401。

## Decisions

- 用可独立测试的恢复函数区分 Authenticated、SignedOut、Unavailable、Superseded；在返回和异常路径核对请求前后的 token。取消始终向上传播。
- UI 在恢复期间只展示恢复页；Unavailable 提供重试且保留会话，只有无会话或 API 确认清除失效会话后才显示登录表单。Superseded 丢弃旧结果并恢复当前会话。
- AuthRepository.me 绑定账号时再次按原 token 原子校验；主线程执行失效回调时确认当前仍无会话，避免影响替换登录。
- 失败日志仅记录异常类型/HTTP 状态，不记录 token、密码或响应内容。
- 会话资料请求使用独立 15 秒总超时，覆盖 DNS、连接与响应等待；不改变业务或 AI 请求时限。避免恢复页面因同步网络等待一直停留在加载中。
- 实机日志捕获到一次 authenticated 后紧接新的 restore started。将认证状态和恢复副作用提升至 PandoraApp 根节点、放在主题内容之外；已拥有当前有效账号时跳过重复恢复，不将已登录页面切回启动加载。
- 使用完整 APK 保留数据覆盖安装，排除热更新覆盖层干扰；不将安装时间与热更新存在本身视为闪动根因。

## Risks / Trade-offs

- 无网络时需要用户重试 → 保留会话并显示清晰恢复失败提示，避免自动重试循环。
- 设备已有登录属于真实账号 → 仅读取必要诊断和 token 是否存在，不输出或清除凭据。
