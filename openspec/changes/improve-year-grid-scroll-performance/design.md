## Context

YearGrid 已按月懒加载并为日期数据做 remember，但每张卡有 28–42 个 Text，滚入新月份时还需构建、测量这些文本及嵌套布局。实机 debug 基线存在长帧，GPU 耗时较低；不能仅凭统计证明唯一瓶颈，也不以 debug 结果承诺 release 帧率。

## Goals / Non-Goals

**Goals:** 减少年卡日期文本布局开销，保持视觉、点击和读屏能力，使用同机同动作前后采样。

**Non-Goals:** 不改业务查询或日/月/周布局，不升级 Compose，不增加打包签名或发布配置。

## Decisions

- 保留月份标题和星期文本；日期数字、今日底色和任务圆点在月份级 drawWithCache 中绘制，缓存 Paint、字体尺寸、基线和日期标签。使用系统默认字体与现有 10sp token，遵循字体缩放。
- 保留每个日期的透明点击/语义单元，提供完整年月日读屏描述；不采用仅 Canvas 加单一手势的方案，以免丢失独立日期辅助访问。
- lazy grid 明确相同月份卡片 contentType，滚动观察只读取 firstVisibleItemIndex；沿用窗口和导航保护。
- 滚动中仅在日历本地更新标题年份；任务年份查询和根页面 cursor 在滚动停稳后再更新，避免跨年惯性滚动中触发根页面重组和任务加载。边缘回中也等待惯性结束，不中途替换 LazyGridState 取消滑动。
- 在同一 debug 包配置、同一手机上执行八次同坐标滑动，记录帧数和分位耗时。若数据不支持改善，明确报告，不将改动数量当成性能收益。

## Risks / Trade-offs

- 原生字体基线与 Compose Text 存在细小差别 → 保留字体尺寸、20dp 文字区和 24dp 单元，通过截图确认。
- 绘制缓存遗漏主题或字体变化 → 使用 drawWithCache 的尺寸/密度失效机制及当前主题颜色闭包。
- debug、JIT、温度及任务数据影响测量 → 同口径记录并披露限制，正式性能仍应在 release 上验证。
