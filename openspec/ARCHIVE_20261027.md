## 主规范合并时保留的现行规则

CLI 先同步各历史增量，再依据已确认需求、当前代码及已有验证记录协调同一能力的后继规则。部分后继变更仍有未完成的客户端/真机验收，本批仅同步已有实现支持的要求，不归档它们、不补勾它们的任务。

- 日报按 `published_at` 所在公司业务日期决定编辑和删除窗口；当天补交昨天/前天的日报当天仍可改，创建范围仍为近三日。旧“补交立即只读”要求不再覆盖现行规则。
- 创始人创建和修改任务免上级审批；普通已生效任务的修改先保存提案，审批期间保留旧内容，通过后替换。派发任务的完成仍由创建者作为上级验收。
- 新旧登录契约并存，`accountIdentifier` 用账号和公司域识别；企业初始化继续要求部署 bootstrap 凭据，不恢复 ADMIN 自行创建企业权限。
- 人员创建使用 Web 随机 16 位初始密码和服务端加密临时交付；不恢复旧页内密码丢失、手工输入初始密码或纯文本交付占位规则。
- 系统日志复用已实现的数据库操作历史，真实版本可为合法 0，未记录的历史版本/名称明确为空；失败操作不作为已提交版本。只覆盖现有操作，不增加任务删除能力。
- Android 任务入口遵循当前服务端能力。当前代码仍有个人任务兼容入口，本次归档未把教师提出的移除入口需求写成已经实现；后续仍需对齐。
- 三个设计/规划能力明确标注为历史交付基线，不把当时的“尚待确认/尚未实现”当作当前运行状态。

已实现后继规则的核对来源包括仍在活动目录的 `journal-created-day-editing`、`founder-task-auto-approval`、`login-and-audit-history-contracts`、`implement-database-operation-audit`，以及当前 `JournalService`、`IdentityService`、`TaskService`、`TaskReviewService`、`OperationLogService` 和 Web/Android 相关页面。
