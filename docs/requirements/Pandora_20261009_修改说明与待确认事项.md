# Pandora 2026-10-09 需求修订说明与待确认事项

## 一、本次修订原则

- 基线采用 `产品需求与设计文档 (1).md` 中**第一套第二章**，没有使用后面的重复旧第二章。
- 按最小必要修改原则处理，不重写技术架构、数据库和第 3～7 章。
- 区分甲方核对意见、组长确认方案、团队实现建议和待确认规则。
- 纯 UI 细节（颜色、间距、抽屉宽度、图标、像素高度等）不写入第二章业务需求。
- 产品展示名称统一使用 **Pandora**；GitHub 仓库 URL 仍保留实际技术地址 `YuzhSong/Pandora6ix`。

## 二、已纳入的主要变化

1. 面向用户的“首页”统一改为“导图”，四个业务面板不变；明确“导图”不是思维导图编辑器。
2. 日志页只负责日志记录、草稿、发布和查询，不再承载任务管理、派发或审核入口。
3. 视图页承担任务查看，并为有任务创建权限的用户提供任务录入入口；正式派发仍需既有审核。
4. 日视图只显示任务，不显示工作日志；周、月视图是否保留日志仍待甲方确认，因此没有擅自删除相关要求。
5. 日、周视图区分全天/日期型任务与定时任务；任务时间支持自定义日期和可选小时、分钟。
6. 普通员工当前版本不允许创建个人任务；创建子任务也必须先具有任务创建权限。
7. 月视图要求完整覆盖月份日期，并在任务过多时提供剩余数量提示或等效查看路径；不再把“固定五周/固定两条”写成业务上限。
8. 视图下钻路径明确为“月 → 周 → 日 → 任务详情”。
9. 补录 9 月 19 日已经明确的日志草稿、发布确认与未保存退出保护。
10. 保留任务审核业务，但审核入口标记为待设计；没有把当前原型保存动作写成正式派发。

## 三、没有写成正式需求的原型/UI细节

- 导图面板尺寸、间距、边框颜色、字体大小。
- 日历每周具体显示 5～6 项、具体任务条高度和像素布局。
- 星形优先级图标本身；第二章只保留 1～5 级重要程度这一当前方案及“语义待确认”。
- 弹层、抽屉宽度、动画形式。
- 24 小时时间轴、定时跨日裁剪等 Codex 实现细节。
- 模拟器、Gradle、JDK、黑屏修复等技术事项。

## 四、仍需甲方/团队确认

1. **周、月视图是否展示日志。** 目前只明确日视图不放日志，因此文档没有擅自删除周、月日志范围。
2. **审核最终入口。** 业务继续保留，但放在哪个页面尚未确定。
3. **最高级发起人的审核方式，以及驳回后“修改原任务重提”方案是否获甲方最终确认。**
4. **日志可选关联任务。** 目前确认的是“不强制关联”；是否保留可选关联及正式任务 ID 关系仍需明确。
5. **任务草稿。** 当前原型草稿不能直接升格为正式业务状态；持久化、可见范围和提交审核方式待确认。
6. **时间边界。** 同日起止时刻相等、跨日定时任务的精确定义尚未确认；没有增加重复任务、时区等规则。
7. **1～5 级重要程度的业务语义与同级排序。** 星形只属于表现方式。
8. **个人十大重要事项联动。** 日志新增、修改或移出最近十天后，已有选中项如何处理仍待确认。
9. **草稿长期保存。** 是否重启后保留、是否跨设备同步和保留期限尚未确定。
