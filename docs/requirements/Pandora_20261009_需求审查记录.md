## 2. 本轮确认的设计输入

- 产品展示名称 Pandora；“导图”是四类信息总览，不是自由编辑思维导图。
- 日志页面只承担日志业务；任务创建入口在视图，任务审核业务保留但入口待设计。
- 日视图只放任务；周、月日志范围尚未确认。日、周支持日期型/全天和定时任务。
- 任务使用统一记录，月历覆盖首尾完整周，月→周→日→任务详情；容量不足应可继续查看，不能形成两条或五周的业务上限。
- 普通员工暂不具备个人任务或子任务创建权限；管理者向管理范围内直属或跨级下级、多人提交派发，直接上级审核后正式生效。
- 多人任务按接收人分别更新进度、提交完成、由发起人验收；不能用 100% 进度或所有子任务完成自动推定父任务完成。
- 日志独立创建，不强制绑定任务；同日可有多条。草稿、发布确认、未保存退出保护已明确，长期草稿保存未定。
- 个人重要事项候选是本人最近十个自然日完整日志，最多选十条；不超过十条默认全部，超过十条由本人选择。个人日志板块没有“最多十条”的限制。

## 5. 原型与正式设计的差别

审查依据还包括当前 `README.md`、`backend/pom.xml`、`web/package.json`、Android Gradle 配置及模拟数据。当前 Android 是离线演示，角色、日志、任务与日期模拟不能证明正式持久化或服务端权限已完成。当前后端只有基础 Web/健康检查依赖，没有 Spring Security、数据访问、数据库驱动或迁移配置。MySQL 原来仍标记为待评估。

因此本次架构中的身份认证、数据访问、业务服务和数据库均是目标设计，非实现结果。新增设计没有修改 Android / Web / backend、现有 OpenSpec 业务变更或三份需求原件。没有执行构建、真实 SQL 或端到端业务验证。
