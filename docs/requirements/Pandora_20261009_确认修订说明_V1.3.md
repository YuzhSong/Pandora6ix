## 1. 依据与确认层级

输入为组长“1009”列出的20条甲方核对意见，再经本对话9项回答细化。本版记录“甲方意见由组长转述”；没有假称独立签字。
最后确认依次为：“正确，确定”“正确，保留”“一篇日志里面的某条工作内容吧”“个人标记完成”“按你说的来”“全企业共用，管理员在web端可以维护”“同时具有全部所选标签…可以不选…日志不需要染色…任务…主标签的颜色”“正确”“都纳入…导图页的消息栏中进行审核…先不实现…预留接口和数据库信息”。

其中主次标签按“一主若干次，不是父子树”采纳建议。日志标签落在整篇日报、本机偏好保存、REST路由/事务/索引为设计提案，不能升级为独立甲方业务确认。UI设计和接口已设计不等于已实现。

## 4. 不是“取消需求”的内容

- 从任务详情移除状态块，不删除审核/执行/验收状态或管理权限。
- 移除日志信封，不取消导图消息、提醒、未来审核。
- 日志不强制关联任务；可选关联仍未决，不恢复强制FR-LOG-05。
- 公司重要事项维护、派发多人/跨级、上级审批及逐人验收为旧需求保留。
- 取消自动下钻不取消手动日/周/月、相邻日期与回到今天。
- 全天任务、连续日期条、月历首尾完整周与更多数据查看保留；不固化“五周、两任务”等LoFi容量为业务限制。
- 本轮不实现消息审批不是“所有任务先免审”；核心生效条件仍为批准。

## 5. 仍待确认

| 编号 | 未决事项 | 为什么不能定案 |
|---|---|---|
| Q-01 | 创始人/无上级申请如何审批 | 没有授权免审或自审 |
| Q-02 | 驳回后重建vs原任务重提；批准后编辑/重审 | 新答复未覆盖既有冲突 |
| Q-03 | 草稿长期存储/同步/期限与任务草稿 | “保留草稿”不等于定义持久化机制 |
| Q-04 | 同分钟起止、跨日定时、业务时区 | 分钟精度不确定端点/时区规则 |
| Q-05 | 1–5重要程度高低及同级顺序 | 星数模型旧方案，不自行推导排序 |
| Q-06 | 已选条目被编辑/过期/移除的联动、补位 | 只确认选条目及保存更新 |
| Q-07 | 上级任务关联、查看、整体完成与统计分母 | 旧US39等未进一步确认 |
| Q-08 | 日报是否保留可选任务关联 | 不强制已确定，可选入口未确定 |
| Q-09 | 标签停用与历史显示；条目独立标签 | 共享/颜色确定，不代表删除及粒度确定 |

不再把个人任务、全部视图无日志、AND筛选、设置范围标为待确认。日报层标签为当前设计粒度，不阻塞文档交付，但实现前评审确认；不新建条目标签关联表。
