# Pandora6ix AI 测试清单

> 用途：把本清单交给 AI 测试代理，结合当前版本的界面、OpenAPI、数据库迁移和已有自动化测试执行。每项都要记录“通过/失败/阻塞/不适用”、证据（请求、响应、截图或日志）和数据 ID。不得使用真实密码、身份证号、手机号或生产数据。

## 维护规则：功能变更必须同步检查清单

本清单是随产品演进维护的测试资产，不是一次性文档。每次提交功能、接口、数据结构、权限、状态流转、客户端页面或外部服务行为变更时，开发者和评审者必须同时完成以下检查：

- [ ] 判断变更是否影响本清单中的已有条目；若影响，更新对应条目的前置条件、步骤、预期结果或权限角色。
- [ ] 为新增功能补充至少一条主流程和一组边界/异常/权限用例；为删除或废弃功能标记条目为“不适用”并写明版本或原因，不直接删除历史覆盖记录。
- [ ] 若变更涉及 API、数据库迁移、状态机、角色权限、通知、AI 或文件格式，必须补充跨模块一致性、失败回滚和兼容性检查。
- [ ] 在同一个 PR/变更说明中记录 Checklist 变更；没有新增或修改用例时，也要说明“已检查，清单无需更新”。
- [ ] 发布前按第 10 节执行回归，并确认本次变更相关条目已经执行；清单未同步时不得将测试标记为完整通过。

以下情况通常无需新增条目，但仍应在 PR 中说明已判断：不改变行为的重构、纯格式化、内部变量重命名、仅更新测试实现且产品契约不变的改动。若判断不确定，按“需要更新”处理。

## 1. 测试前置检查

- [ ] 明确被测版本、分支、提交 SHA、环境地址和时区（默认 Asia/Shanghai）。
- [ ] 确认 Android、Web、Backend 可独立启动；确认 Flyway 迁移成功且使用隔离测试数据库。
- [ ] 准备至少两个企业 `E1`、`E2`，每个企业包含根组织、部门、团队和人员。
- [ ] 准备角色：ADMIN、普通管理员/主管、普通员工；另准备已停用员工和无权限跨企业账号。
- [ ] 每个关键对象准备“创建者、被授权者、无权限者、已删除/停用关联者”四类账号。
- [ ] 测试数据包含空数据、1 条、边界数量、重复值、超长文本、Unicode/emoji、前后空格和特殊字符。
- [ ] 记录可用入口：Web 登录地址、Android 包/模拟器、API Base URL、健康检查地址、测试账号和重置方法。
- [ ] 确认网络可模拟：超时、断网、慢响应、5xx、重复请求和响应乱序。
- [ ] 测试前后保存数据库快照或可重建脚本；测试结束清理临时账号、文件和推送设备。

## 2. 通用 AI 执行规则

- [ ] 先读取 `README.md`、模块 README、`backend/openapi.json`、相关 OpenSpec 和现有 `web/tests`，再设计具体步骤，不臆测不存在的功能。
- [ ] 每个功能至少生成：主流程、空值、最小值、最大值、越界值、重复提交、取消/返回、刷新/重启、权限拒绝、网络失败、并发冲突用例。
- [ ] 对每个写操作验证 UI 提示、HTTP 状态、响应结构、数据库持久化、刷新后的结果、操作日志和通知（若适用）。
- [ ] 同一断言至少用 UI 观察和 API/数据库/日志中的一种独立证据交叉验证。
- [ ] 发现失败后先保存现场并最小化复现，不自动重试覆盖 409、401、403、422 等有诊断价值的响应。
- [ ] 不绕过登录、权限、版本号、审批或确认弹窗；不直接修改数据库来制造“通过”。
- [ ] 所有时间测试覆盖本地日界线、月份/年份切换、夏令时差异（若部署环境启用）和客户端/服务端时区差异。

## 3. 身份认证与会话

- [ ] 正确的企业标识、登录名、密码登录；错误密码、未知账号、空字段、大小写和前后空格行为正确。
- [ ] 未登录访问 `/api/v1/*`、管理页和 Android 受保护页面均被拒绝；健康检查按设计可访问。
- [ ] Token 缺失、格式错误、过期、伪造、属于 E2 的 Token 访问 E1 均返回正确错误，不泄露数据。
- [ ] 刷新页面、关闭/重开浏览器、多个标签页、登出后返回历史页的会话行为正确；不把密码/初始密码/Bootstrap token 写入 localStorage 或日志。
- [ ] 修改密码成功后旧密码失效、当前会话按约定失效，新密码可登录；失败修改不改变密码。
- [ ] 重复登录、重复登出、网络中断后重试、并发修改密码不会产生异常状态。
- [ ] 登录失败、登出、改密和敏感操作具备必要的操作日志，响应不包含密码哈希或密钥。

## 4. 企业、组织与人员管理（Web）

- [ ] 企业/根组织展示与登录标识区分；E1 管理员看不到 E2 数据。
- [ ] 创建部门/团队：必填、重名、超长名称、空白名称、特殊字符、父节点不存在、将节点挂到自身/后代等情况。
- [ ] 根组织不可删除；有下级组织、人员（含停用人员）时删除被阻止并说明原因；空团队删除后列表和详情同步更新。
- [ ] 组织类型双向转换、层级移动、负责人/主管设置符合约束；循环引用、跨企业 ID、无效负责人被拒绝。
- [ ] 新建人员同时创建账号；必填字段、身份证号/电话格式、重复登录名、默认角色、初始密码交付均正确。
- [ ] 历史人员可逐项补齐资料但不能清空已填字段；无权限人员不能查看完整身份证号或修改他人资料。
- [ ] 离职、岗位变更、主管替换、停用/恢复的前置条件、历史记录、角色保留和下属任务影响正确。
- [ ] 批量 CSV：空文件、表头错误、编码、重复行、部分合法、全部非法、1/100/上限+1 条、导入中断和重复提交。
- [ ] 账号交付/凭据重置：只显示一次有效初始密码，旧版本失效，刷新/重登不泄露新密码，下载/复制内容准确且不落盘到不安全存储。
- [ ] 头像上传为空、非图片、超大、损坏图片、重复上传、跨用户访问和缓存刷新行为正确。

## 5. 任务、审批与执行闭环（Android + Backend）

- [ ] 创建一次性任务、循环任务和不同时间类型；标题/内容为空、超长、过去时间、日界线和重复标签均验证。
- [ ] 任务接收人候选集只包含授权范围内且启用的人员；跨企业、停用人员、无直属关系不能被选择。
- [ ] 任务状态完整覆盖：草稿/待审批/已分配/执行中/待验收/已完成/驳回/取消（以实际状态为准），每次转换检查合法性。
- [ ] 直属上级、部门负责人和管理员的查看、编辑、审批、验收权限分别验证；普通员工不能越权操作。
- [ ] 执行人提交进度、完成、补充说明、附件/空内容和重复提交；审批通过、驳回、再次提交和撤回行为正确。
- [ ] 过期任务、未来任务、跨月循环、闰年 2 月、月末日期和重复生成不多不少；删除/取消后不再生成实例。
- [ ] scoped edit/status 只影响允许范围；修改已完成任务、他人任务和不存在任务返回明确错误。
- [ ] 审批/完成请求重复决策、过期决策、同时决策、错误版本号返回 409 或约定错误且状态不被覆盖。
- [ ] 日历按日/周/月切换、空状态、分页/加载更多、刷新、跨时区和任务详情跳转一致。
- [ ] 通知未读数、已读、重复通知、推送设备注册/注销、无效 installationId 和推送服务不可用时主流程仍可用。

## 6. 工作日志、重要事项与统计

- [ ] 新建、查看、删除工作日志；日期、内容、条目为空/超长、重复点击保存、刷新和离线失败均验证。
- [ ] 日志列表按日期/权限过滤；员工、主管、管理员看到的范围与产品规则一致，跨企业不可见。
- [ ] 评论新增/删除、空评论、超长评论、重复提交、无权限删除和日志删除后的级联行为正确。
- [ ] 重要事项候选、标记/取消标记、公司重要事项发布/修改/查看权限和重复操作正确。
- [ ] Dashboard、task-items、statistics 的空数据、极值、时间范围反转、超大范围、分页和汇总准确。

## 7. Web 管理界面与客户端体验

- [ ] 首次加载、慢网、接口 401/403/404/409/422/500、超时和空响应都有可理解的加载/空/错误状态。
- [ ] 表单键盘操作、焦点、回车重复提交、取消后数据恢复、浏览器后退/刷新和未保存草稿行为正确。
- [ ] 长名称、长文本、窄屏、放大字体、中文/英文/emoji 不溢出或遮挡；桌面和移动视口均检查。
- [ ] 分页、搜索、排序、筛选、日期范围和清空筛选组合后结果正确；切换页面不串数据。
- [ ] 下载 Excel/文本内容、文件名、编码、空结果、特殊字符和大数据量正确；不下载敏感字段到不应包含的文件。
- [ ] 操作日志筛选（关键字、模块、动作、来源、结果、时间、cursor/snapshot）分页稳定，详情与列表一致。

## 8. API、数据一致性与安全

- [ ] 所有 Controller 路径、方法、Content-Type、必填字段、枚举、分页参数和错误格式符合 `backend/openapi.json`。
- [ ] 缺字段、null、错误类型、超大整数、负数、未知枚举、重复 JSON 字段、非法日期和超大请求体均被安全拒绝。
- [ ] 资源 ID 枚举、越权修改/删除、路径穿越、脚本注入、SQL 注入、恶意文件上传和响应信息泄露检查。
- [ ] 写操作幂等键、重复请求、网络重试和客户端超时不会重复创建任务、人员、日志或通知。
- [ ] 乐观锁/`expectedVersion`：旧版本更新返回 409；重新读取后可继续操作；失败不会部分提交。
- [ ] 事务边界：人员与账号、任务与分配、审批与通知、删除与关联数据要么全部成功要么全部回滚。
- [ ] H2 持久化重启后数据、Flyway 迁移、唯一约束、外键/级联、软删除和时间字段仍正确。
- [ ] 所有失败写操作生成必要审计记录，日志不包含密码、Token、身份证完整值或第三方密钥。

## 9. AI、外部服务与可靠性

- [ ] AI 输入为空、超长、包含敏感信息、提示注入、Unicode 和重复请求；确认脱敏规则生效且不回显敏感数据。
- [ ] AI 正常响应、格式错误、超时、限流、配额耗尽、第三方 5xx、响应乱序和重复回调均有稳定处理。
- [ ] AI 结果不可用时页面给出可恢复提示，不阻塞任务/日志主流程，不把模型原始错误暴露给用户。
- [ ] JPush/推送服务不可用、设备重复注册、注销后推送、消息顺序和通知去重行为正确。
- [ ] 连续刷新、并发 2/5/20 个客户端、批量 100/上限+1 条数据下，检查响应时间、错误率、数据库锁和资源是否异常。

## 10. 发布回归与验收门槛

- [ ] Backend：`mvnw verify` 通过；Web：`npm test`、`npm run lint`、`npm run build` 通过；Android：`assembleDebug` 与 `testDebugUnitTest` 通过。
- [ ] Web 真实后端联调 `npm run test:integration` 通过，且使用临时数据库，不连接团队共享/生产数据。
- [ ] 主流程冒烟：登录 → 查看组织/人员 → 创建任务 → 执行 → 审批/验收 → 查看日志/通知 → 登出。
- [ ] 回归范围覆盖本次变更涉及的模块、API、数据库迁移、权限矩阵和客户端版本兼容性。
- [ ] 阻断级问题为 0；高优先级问题有明确豁免人、原因、风险和回归计划；测试报告包含环境、数据、证据和未覆盖项。

## 11. 给 AI 测试代理的执行模板

```text
你是 Pandora6ix 的测试代理。先读取 README.md、对应模块 README、backend/openapi.json、相关 OpenSpec 和现有测试，确认功能边界后再执行。
目标版本：<commit SHA>
测试环境：<URL/模拟器/API>
账号：仅使用已授权的匿名测试账号，禁止输出密码、Token、身份证和手机号原文。
本轮范围：<功能/接口/页面>
必须覆盖：主流程、空值、边界、异常操作、权限隔离、重复提交、并发/版本冲突、刷新/重启、网络失败、数据持久化。
每条结果输出：ID、前置数据、步骤、预期、实际、证据、严重级别、是否可复现、建议修复方向。
失败时：先保存请求/响应/截图/日志和数据 ID，再最小化复现；不要自动重试可能改变状态的写请求。
结束时输出：通过率、失败列表、阻塞项、未覆盖风险、建议新增自动化测试。
```

## 12. 缺陷记录最小字段

`严重级别`（Blocker/Critical/Major/Minor） · `模块/接口` · `版本 SHA` · `账号角色/企业` · `前置数据` · `复现步骤` · `预期/实际` · `请求 ID/响应` · `截图或日志` · `复现概率` · `数据清理状态`。
