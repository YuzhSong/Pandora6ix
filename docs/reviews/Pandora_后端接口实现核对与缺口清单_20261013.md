## 5. 公共能力仍有哪些缺口

- **业务成功响应**：后端没有 `{data,requestId}` 业务响应实现。`/health` 裸 JSON 是存活协议；Web 新增显式健康适配不改变业务成功信封要求。
- **业务错误 DTO**：当前 [ApiError](../../backend/src/main/java/com/pandora6ix/backend/api/error/ApiError.java) 为平铺 `{timestamp,status,code,message,path,requestId}`，没有草案的 `error` 包裹和 `fieldErrors`。Web 已兼容平铺/嵌套错误，但正式后端契约仍需统一；框架错误基础处理已实现，不能把它列为完全没有。
- **并发、原子性、幂等**：没有资源 version/expectedVersion 校验、业务 409、数据库事务、发布/提交幂等实现。
- **分页和筛选**：没有 cursor/limit、稳定排序、任务标签 AND、区间授权查询等后端实现。
- **业务时区**：缺少配置与业务日统一计算；Q-04 未确认前不得从客户端时区自行推导业务日及跨日端点。
- **数据层**：[pom](../../backend/pom.xml) 无 JDBC/JPA/数据库驱动或迁移依赖；源码无实体、业务 repository、业务 migration/datasource。MySQL 是设计候选，实施技术和迁移需确认；设计文档中的表不是实际建表。
- **身份与权限**：无登录/会话实现，也没有对应安全依赖或自定义授权实现；[WebConfig](../../backend/src/main/java/com/pandora6ix/backend/config/WebConfig.java) 只注册请求标识过滤器。服务端企业隔离、直属/跨级范围、对象归属与角色变更验证均未实现。
- **接口验收**：当前 9 个后端测试覆盖启动/健康、基础错误和状态码，不覆盖业务成功、越权、并发、唯一日报或跨端共享；暂无正式 OpenAPI 及业务测试数据。实际业务性能也尚未验收。

## 6. 预留、待确认和客户端职责

### 本轮按设计预留：尚未实现，不混入当前 Web 接入必交清单

- API0.1 第 9 节的 `GET /inbox`、`PATCH /inbox/{id}/read`、`GET /task-reviews`、`GET /task-reviews/{id}`、`POST /task-reviews/{id}/decision` 全部为 Reserved。
- 导图消息审核入口/消息服务按 FR-NOTIFY-02 本轮仅预留。**审批后生效仍是任务核心约束**，不能因入口预留就把任务创建自动设为已批准。
- 新任务/截止提醒、工作邀约/请示为 P1 扩展；AI 关键词/总结/建议为 P2 扩展。没有实现或完整本轮执行契约，不能称为已完成业务，也不能擅自纳入这次合并的后端开发范围。

### 契约需要确认后再实施

| 未决项 | 对后端实施的影响 |
|---|---|
| Q-01 | 创始人/无上级如何审批，不自动免审或自审 |
| Q-02 | 驳回后重建/原任务重提、批准后编辑/重审；`PATCH /tasks/{id}` 为 Conditional，resubmit 为 Pending |
| Q-03 | 日报/任务草稿长期保存、同步和期限 |
| Q-04 | 同刻、跨日定时端点、业务时区 |
| Q-05 | 重要程度高低语义和同级排序 |
| Q-06 | 已选条目编辑/过期/移除的联动、补位和删除权限 |
| Q-07 | 父子任务关联/查看范围、整体完成和统计分母 |
| Q-08 | 日报可选任务关联是否保留；强制关联已取消 |
| Q-09 | 标签停用/历史显示、逐条工作内容独立标签；不自行加删除接口 |

字体/显示大小、主题等按账号保存在本机；当前需求没有后台同步偏好 API。草稿提示、发布确认、退出未保存确认是客户端交互；服务端要保护正式发布及业务原子性，不据此虚构草稿同步接口。年视图是现有 Android 原型能力，API0.1 的 calendar 草案目前只有 day/week/month；其数据接入方式需评审，可通过授权任务区间查询提供，不能声称已有正式 `mode=year` 契约。

## 8. 建议交付顺序

1. 先评审身份域/会话、企业初始化、人员/组织/角色、存储与隔离契约，并交付实现、迁移、受控测试数据和权限测试，解除 Web P0。
2. 交付共用标签和公司事项，统一成功/错误 DTO、分页和版本冲突；Web 改用真实 HTTP repository 后再验证 Android 共享数据。
3. 交付任务/@候选、日报/工作条目、个人选择、日历/导图读模型及 P0 个人统计，依赖同一身份和持久化基础。保留审批约束，不把表单保存当正式生效。
4. 根据已确认规则补齐完成/逐人验收与统计验证；对 Q-01～09、Reserved 与 P1/P2 扩展分别立 OpenSpec，不用假定规则填补缺口。

每个实施批次应提交相应 OpenSpec、明确 DTO/错误样例、业务和权限测试、版本冲突与跨端联调结果。本报告提供待实现清单，不将设计路由改为已上线接口。
