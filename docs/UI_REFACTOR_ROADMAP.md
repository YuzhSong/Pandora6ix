# Pandora Android UI 统一化改造路线

2026-10-31，适用 [审计基线](UI_AUDIT_REPORT.md) 和 [Design System 1.0](ANDROID_UI_DESIGN_SYSTEM.md)。本次只交付审计与规范；下表全部为后续迁移，尚未实现，不把文档勾选当成运行验收。

## 1. 顺序、范围与退出条件

P0=影响全局一致性的基础问题，P1=业务页面/组件一致性，P2=细节与反馈。优先级不代表本轮发现业务崩溃。每批单独OpenSpec/聚焦提交，在用户指定工作分支推进；不擅自建分支或并行重构团队代码。

| 顺序 | 优先级 | 改造区域 | 复用/合并 | 完成标准 |
|---:|---|---|---|---|
| 1 | P0 | theme/Theme.kt及未来Color/Type/Shape/Dimens | 同key生成LocalAppTheme与M3；旧别名转接 | 五主题按钮文字≥4.5:1；主题退出重启仍保存；页面逻辑零变更 |
| 2 | P0 | 浮层、日期/时间、退出确认、历史日志日期选择 | PandoraDialog/Sheet，清理各自遮罩/背景覆盖 | 五主题全部白底；24角/40%遮罩；键盘/Back/未保存保护不变 |
| 3 | P0 | 主要提交/保存/确认、输入组件 | PandoraButton/TextField；普通动作不再用标签色 | 48触达，禁用/加载/错误齐全；不影响幂等与权限 |
| 4 | P1 | 汇总、成员详情、全部任务/日志列表 | SummaryPanel与基础Panel；TagChip/StatusChip/Avatar | 3面板、3/4/3预览；360dp四直属可见；长字可放大；条目有边界 |
| 5 | P1 | 任务详情/新建/编辑/执行进度 | DetailCard/SectionCard基础容器合并；现有TaskEntrySheet继续复用 | 标签一致原色/主标签前置；执行记录内联；接收人姓名无回退ID；审批/重复修改范围不变 |
| 6 | P1 | 我的/设置/审批队列与详情 | SettingsCard/Review SectionCard/PersonRow共享基础；QueueTab统一 | 审批/设置在组织前；米白普通卡+灰边；评论IME不遮挡 |
| 7 | P1 | 导图四板块/展开/事项选择/通知抽屉 | HomePanel适配Token；覆盖Card改统一Overlay基础 | 保留四板块及勾选上限/数据范围；去2dp彩边/重阴影；不添统计卡 |

| 10 | P1 | 登录/标签管理/AI占位 | 共用表单/按钮/空态；已有图标 | 无新页面；品牌Display受限；标签色块可访问 |
| 11 | P2 | Snackbar、TalkBack、焦点、动画 | 暂态提示统一，inline错误保留 | 200ms非装饰过渡；系统关动画可用；关闭浮层焦点返回 |
| 12 | P2 | 移除旧别名/重复基础样式 | 清理迁移完成区域，不重排业务目录 | 新页面无本地Hex/自定义常规dp；例外全部登记；重跑审计并保留前后对照 |

## 2. 迁移规则与风险

- 第一批新增基础Token和适配，不一次替换全App。保持现有颜色别名临时可用，明确deprecated目标；禁止同时保留两套“最终规范”。
- 先迁移高复用基础，再按业务页面推进。HomePanel、SummaryPanel等业务组合仍保留名称；仅合并背景/角/边距包装。不要把TaskDto塞进通用Panel造成业务耦合。
- 白色模态要检查所有自制Card覆盖和Dialog根Surface，不能仅看AlertDialog。JournalDatePicker当前全屏Dialog是明确漏点。
- 标签使用真实服务端色，不新增API、表、假数据或改已有记录。新标签默认色板的改变若涉及持久化语义，另提明确范围。
- UI显示权限只能沿用已有capabilities/allowedActions与服务端限制；禁用样式不能替代鉴权。无权限、错误和空数据仍分开。
- 日历视觉密度属于高风险区域，先建立截图与布局回归，再修改绘制Token；不得为了统一dp修改任务区间算法。
- 深色模式目前没有实现；本轮不新增暗色模式，也不把五种浅色主题称为暗色适配。

每批有独立可撤回提交；回退仅该批视觉适配，不撤回团队业务功能，不覆盖用户未提交文件。实际发布/推送/PR合并另按用户授权和仓库流程进行；本文不视为要求直接发布。

## 3. 可执行验收清单

### 每批代码门槛

1. 仓库根运行 `python docs/tools/android_ui_inventory.py`，提交受影响的清单；对照基线判断新增数字是否已有Token。
2. 在 `android` 执行 `./gradlew.bat :app:assembleDebug :app:testDebugUnitTest`。行为未变的尺寸调整不写镜像实现测试；对状态映射/颜色对比等纯逻辑添加有价值的回归。
3. 执行该批 `openspec validate <change-name> --strict` 和 `git diff --check`。不把已有全局lint阻塞隐去；若执行lint需独立报告结果。
4. 检查差异没有Repository/API/DB/权限/导航变化；需要修改时暂停UI批次，另立确认范围。

### 页面验证矩阵

| 维度 | 最小覆盖 | 检查 |
|---|---|---|
| 宽度 | 360、393、600dp，横屏抽查 | 四列、长标题、按钮增长、浮层限宽 |
| 字体 | 1.0、1.3、2.0 | 无裁切、正文可读、滚动到底；日历允许概览下钻 |
| 主题 | warm/mint/sky/sakura/lilac | 表面三层、白色浮层、主色/状态一致、持久化 |
| 系统 | 手势/三键、IME打开/关闭、刘海 | 不双算Insets、底栏/提交条不挡内容 |
| 角色 | 普通员工/负责人/创始人，按现有测试账号权限 | 未授权按钮不出现/失败如实展示，不测试越权绕过 |
| 数据 | 空/少/多/超长中文/多标签/多接收人/接口错误 | 明确区分加载/空/错误/无权限，重试不重复提交 |
| 可访问性 | TalkBack、48dp命中、焦点、对比度计算 | 图标命名、状态非纯颜色、关闭弹窗返回焦点 |

至少保留：五主页面、日周月年、汇总/成员/全部列表、任务创建/编辑/详情/执行、日志编辑/详情/历史、审批两个队列/详情、设置/标签、日期/时间/确认浮层的前后截图。图片用测试数据和现有账号授权，不为截图修改生产任务或头像。保存截图名称、分支SHA、宽度/fontScale/theme与设备，不能只写“肉眼正常”。

### 关键业务守护

- 五导航顺序和返回关系；导图四板块数据范围；汇总有限预览和全部列表完整授权数据。
- 任务个人/派发/全公司标记、审批后生效、重复单次/未来范围、分接收人验收/驳回重提仍走原流程。
- 日志唯一日报、草稿和退出保护、完整详情；任务/日志不被颜色更改影响权限。
- 头像跨页共享、主题跨重启保存、电话隐私状态如实显示。
